## 目标与实现边界

将论文结构稿第 3.1、3.2 节的聚合延续机制实现为可执行协议原型。核心场景是：服务更替时，一个实例还在接收更新，另一个已经获得开启授权；后继分别延续前者、发布后者，并允许新的训练实例推进。

首版复用 `abstract_threshold_backend.py` 的份额状态、交接记录和开启授权，新增 `reconfigurable_async_fl.py` 组织本文的训练行为。原 `reconfigurable_fl_sim.py` 保留历史策略比较；DyCAPS 和 Buffalo 的复现保留为后续真实组件接入依据。三个上游仓库保持原样。

首版使用明文数值作为聚合参考值，事件序列代表已经认证并取得一致的操作。它验证协议规则与训练结果的关系。真实密文、异步一致消息、持久副本和安全清除分别接入对应组件。运行结果属于功能验证，性能表使用后续真实实现的数据。

## 协议对应

| 论文中的处理 | 首版代码行为 | 检查依据 |
|---|---|---|
| 客户端纳入 | 固定实例、基础版本、更新标识、客户端、权重和向量；一个客户端每实例一次 | 重传返回原纳入结果；冲突与跨实例重复使用拒绝 |
| 活动实例延续 | 冻结已纳入集合；安装后继、原组退役、后继激活 | 激活前等待；激活后迟到更新继续进入同一实例 |
| 已授权实例处理 | 保持原开启授权与份额代数；当前服务提交恢复出的结果 | 服务变化时仅收集原授权成员的贡献 |
| 结果固定 | 聚合恢复、结果提交和模型应用分开执行 | 重复提交返回相同位置；应用按提交顺序且每实例一次 |
| 并发训练 | 新服务创建新实例；旧实例各自等待必要条件 | 一个实例交接等待期间，另一个实例可以完成 |
| 移动腐蚀观察 | 按实例份额代数累计已暴露成员，释放腐蚀保留历史 | 超过预算标记轨迹超出模型；保留两代材料时分别统计 |

数值参考采用

$$
Y_{sid}=\frac{\sum_u b_u\Delta_u}{\sum_u b_u},\qquad
w_{t+1}=w_t+\eta\frac{Y_{sid}}{1+t-v_{sid}}.
$$

首版固定 $h(a)=1/(1+a)$，用有理数精确比较轨迹；这是一种可替换的陈旧度权重，不构成收敛结论。缓冲人数、开启门限和服务确认人数分别设置。

## 验收方法

`python3 experiments/check_our_protocol.py` 应执行完整双实例轨迹及乱序、重复、延迟、成员离线和腐蚀预算检查，并生成公开的功能检查摘要。`python3 experiments/check_abstract_protocol.py` 继续验证复用组件的原行为。

主场景要求：旧组接受的两个更新跨交接保留；第三个更新到达后直接参与原实例；已授权实例沿原授权恢复；后继确认的结果只应用一次；模型数值与相同纳入集合、权重和应用顺序的直接计算一致。

## I1：独立协议内核，2026-09-21

### 已执行的流程

`AggregationProtocol.dispatch` 接收操作与参数，记录 `accepted`、`pending`、`duplicate` 或 `rejected`。调用方负责在条件满足后重新投递等待操作。更新身份、参与集合、基础版本、样本权重和实际向量由协议维护；既有后端负责抽象份额状态。

1. A 组为活动实例接受 $(1,2)$、$(4,-1)$，权重分别为 1、2；另一实例已满额并固定开启授权。
2. B 组接任后，活动实例固定原输入，等待安装、退役和激活；已授权实例保留 A 组的贡献者集合。
3. 等待期间，B 组的新实例先完成并应用结果。
4. 活动实例激活后接受迟到的 $(-2,-1)$，权重为 1，沿用原训练计算，恢复 $Y=(7/4,-1/4)$。
5. A 组成员为原已授权实例交付贡献；B 组确认结果。模型应用按新实例、活动实例、原已授权实例的顺序完成，最终为 $(53/24,-35/24)$。
6. C 组接任后继续读取既有结果及其应用位置；同时可以创建基于新模型版本的实例。

代码把后端的 `combine_open` 视为聚合恢复，其内部历史状态名 `committed` 仅属于抽象组件。本文的结果提交由独立的 `commits` 记录表示，`apply_result` 再执行模型应用。三个事件分别检查。

### 检查与结果

```bash
python3 experiments/check_our_protocol.py
python3 experiments/check_abstract_protocol.py
python3 -m py_compile experiments/reconfigurable_async_fl.py experiments/check_our_protocol.py
```

以上命令通过。结果为 `results/our-protocol/summary.json`，完整主轨迹为 `results/our-protocol/events.json`。主轨迹 66 个事件逐项重放后得到相同响应、提交记录和模型。

额外检查覆盖六种安装、退役、激活顺序；参与权重与更新标识冲突；一个客户端多次贡献；维度和模型版本不符；贡献者离线后的已保存贡献合并；当前服务人数不足时等待提交；两次不相交更替；两代成员重叠；腐蚀释放后的累计暴露；新份额生成前已腐蚀的成员；后继安装后旧份额仍在时的暴露统计。

### 当前实现条件

- 事件代表理想认证和一致决定；在线人数检查是参考参与门槛，异步一致协议的活性由后续真实组件检验。
- `install` 在一次理想操作内完成重分享和安装确认；数值前缀保存在当前内存中。网络传输、载荷副本和独立后继进程恢复随后接入。
- `retire` 表示外部已经满足清除条件的理想通知；代码结束对应暴露观察。它自身不生成清除证明，内存中的明文参考向量也不作为隐私实现。
- 腐蚀操作观察各实例各代的份额暴露，超预算保留轨迹并标记。恶意发送、接收私钥暴露以及服务认证密钥尚由真实组件阶段补齐。
- 当前更替等待全部在途交接完成后才接受下一次服务更替；各实例和新训练仍可并行。允许多组交接同时悬而未决，需要进一步实现逐实例的服务链追赶。
- 重放用于功能恢复检查。持久存储、崩溃后的原子模型更新、实际客户端 SGD 与墙上时间调度属于后续系统接入任务。

这一步建立了本文的训练与成员变化规则。下一轮优先替换理想交接和开启，使同一双实例轨迹通过真实密文与后继进程执行。

## I2：端到端训练闭环，2026-09-21

### 实现内容

`experiments/flsystem` 现在提供统一入口 `python3 -m experiments.flsystem`，把客户端本地训练、系数保护、服务组交接和模型应用放在同一条可运行流程中。

- 客户端使用 PyTorch 在合成二分类数据上执行本地 SGD，训练函数位于独立模块，支持 `spawn` 进程并行。
- 客户端将模型更新量量化为整数系数，使用 DyCAPS BLS 加法密文保护；服务进程完成密文累加和门限开启。
- A 服务组可以把仍在接收更新的实例交给 B 服务组；交接载荷包含已有聚合密文、更新标识和 DyCAPS 的加密协议消息。
- B 服务组完成后继份额安装和刷新后继续接收迟到更新；已完成实例沿原授权成员开启，结果只应用一次。
- 构建过程在临时 DyCAPS 副本中加入实验工作进程，不修改 `experiments/upstream/dycaps`。

### 小规模运行结果

```bash
python3 -m experiments.flsystem \
  --rounds 3 --clients 3 --local-steps 2 \
  --output experiments/results/fl-system-run3
```

运行结果保存在 `experiments/results/fl-system-run3/`：

- 完成 3 个聚合实例，接收 9 个客户端更新。
- A→B 交接成功，两个实例携带交接载荷，其中一个保留 2 个已接收更新。
- 独立明文参考聚合与密文开启结果一致。
- 模型应用顺序为 `aggregation-1`、`aggregation-0`、`aggregation-2`，事件重放得到相同模型。
- 测试集准确率从 `0.482` 提升到 `0.914`；该数值仅用于验证训练闭环，不作为论文实验结论。

### 当前边界

这一步验证了本文协议机制能够承载真实本地训练和真实密文聚合。它仍然使用本地进程间管道、合成数据、理想化的服务变更决定和诚实开启成员。崩溃后的 live state 恢复、实际异步网络、恶意客户端、可验证开启以及受限移动敌手下的隐私实验仍需分别接入。

## I4：动态交接机制对照实验，2026-09-21

本实验使用已有事件模拟器比较 `static`、`periodic-rekey`、`selective-finality` 和 `full-transfer`。统一轨迹包含 3 次成员变化、28 个实例、节点离线与恢复、在途更新、交接放弃和客户端重提交。实验代码和结果：

```bash
python3 experiments/generate_reconfigurable_trace.py \
  --transitions 3 --windows-per-configuration 4 \
  --clients-per-window 3 --nodes 6 --seed 17 \
  --include-membership-events --include-handoff-abandonment \
  --output experiments/results/academic-reconfigurable-trace.csv
python3 experiments/reconfigurable_fl_sim.py \
  --trace experiments/results/academic-reconfigurable-trace.csv \
  --protocol all --nodes 6 \
  --output experiments/results/academic-reconfigurable-results.csv \
  --event-output experiments/results/academic-reconfigurable-events.csv
```

关键结果保存在 `academic-reconfigurable-summary.json`：

| 协议 | 完成封存 | 放弃实例 | 接收更新 | 重提交 | 状态恢复 |
|---|---:|---:|---:|---:|---:|
| `full-transfer` | 25/28 | 3 | 50 | 12 | 6 |
| `selective-finality` | 25/28 | 3 | 50 | 12 | 6 |
| `static` | 1/4 | 0 | 8 | 0 | 0 |
| `periodic-rekey` | 1/4 | 0 | 8 | 0 | 0 |

该实验说明交接策略对在途计算保留和成员变化后的继续训练有直接影响。`full-transfer` 平均交接延迟为 2.214 个事件，`selective-finality` 为 6.643 个事件；静态和周期重密钥策略无法延续跨配置实例。结果衡量协议连续性与计算保留，不替代真实数据集上的模型收敛实验。

## I5：参数扫掠与训练接口，2026-09-21

PyTorch 训练入口已经存在于 `experiments/flsystem/`，当前环境可运行 CPU 版 PyTorch。后续更强设备只需替换训练负载和数据集；协议事件、实例身份、成员变化和指标字段保持一致。

在不依赖 PyTorch 的条件下，已完成 5 个随机种子、1 至 3 次成员变化、每配置 4 个实例和每实例 3 个客户端更新的扫掠。结果文件为 `experiments/results/academic-reconfigurable-sweep.json`：

| 协议 | 封存实例 | 接收更新 | 重提交 | 状态恢复 | 平均交接延迟 |
|---|---:|---:|---:|---:|---:|
| `full-transfer` | 270/300 | 540 | 120 | 60 | 3.494 |
| `selective-finality` | 270/300 | 540 | 120 | 60 | 6.003 |
| `static` | 15/60 | 120 | 0 | 0 | 0 |
| `periodic-rekey` | 15/60 | 120 | 0 | 0 | 0 |

统一接口确定为：生成器输出 CSV 事件轨迹，协议模拟器从 CSV 重放，真实 FL runner 使用同一事件顺序驱动客户端训练和密文提交。当前 Python 生成器通过 CSV 完成字段类型转换，后续训练设备直接读取该轨迹，不再复制成员变化逻辑。
